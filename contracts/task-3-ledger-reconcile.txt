# Task 3: Ledger Reconciliation Evidence

## Carry Flow Reconciliation

### Initial State (After Settlement)
```
Per Request:
- entitlement = gross_assets_before_carry
- accrued = entitlement * carry_rate
- carryRemaining = accrued
- claimed = 0
- carryDeducted = 0
- assetsClaimable = entitlement - accrued

Cohort Aggregates:
- cohortTotalEntitlement = Σ(entitlement)
- cohortTotalClaimed = 0
- cohortCarryRemaining = Σ(carryRemaining)
```

### After Partial Redemption
```
Per Request:
- claimed += assets_received
- carryRemaining -= carry_deducted
- carryDeducted += carry_deducted
- assetsClaimable -= assets_received

Conservation Check:
- assetsClaimable + claimed == entitlement - accrued ✓
- carryRemaining + carryDeducted == accrued ✓
```

### After Full Redemption
```
Per Request:
- claimed = entitlement - accrued
- carryRemaining = 0
- carryDeducted = accrued
- assetsClaimable = 0
- status = Claimed

Conservation Check:
- claimed == entitlement - accrued ✓
- carryDeducted == accrued ✓
```

### Cohort Conservation
```
Invariant: cohortTotalClaimed + cohortCarryRemaining <= cohortTotalEntitlement

At any point:
- cohortTotalClaimed = Σ(claimed)
- cohortCarryRemaining = Σ(carryRemaining)
- cohortTotalEntitlement = Σ(entitlement)

Verification:
Σ(claimed) + Σ(carryRemaining) 
  = Σ(claimed + carryRemaining)
  = Σ(entitlement - assetsClaimable) [from per-request conservation]
  <= Σ(entitlement) [since assetsClaimable >= 0]
  = cohortTotalEntitlement ✓
```

## Loss Attribution

When loss is realized:
1. Reduce `accrued` by loss amount
2. Reduce `carryRemaining` by loss amount
3. Update cohort aggregates accordingly
4. Conservation: `accrued - loss + carryRemaining - loss == accrued + carryRemaining - 2*loss`

## Deterministic Properties

1. **Settlement Determinism**: Given same frozenAssets, frozenShares, and proRataRatio,
   entitlement calculation is identical for all requests

2. **Carry Calculation**: carry = (entitlement * carryAmount) / PRORATA_PRECISION
   - Uses same PRORATA_PRECISION (1e18) across all calculations
   - Prevents rounding inconsistencies

3. **Sequential Safety**: Multiple redemptions preserve invariants because:
   - Each updates claimed and carryRemaining atomically
   - No intermediate state violates conservation equations

## Off-Chain Reconciliation

On-chain ledger state can be reconciled with off-chain records using:
```
For each request:
  expected_claimed = total_assets_claimed_from_request
  expected_carryRemaining = initial_carry - total_carry_deducted
  
  assert request.claimed == expected_claimed
  assert request.carryRemaining == expected_carryRemaining
```

## Edge Cases Handled

1. **Zero carry**: accrued = 0, carryRemaining = 0, entitlement = assetsClaimable
2. **Full carry (100%)**: assetsClaimable = 0, all value goes to carry
3. **Partial claims**: Conservation maintained at each partial claim
4. **Dust claims**: Special handling for sub-threshold amounts when finalized
