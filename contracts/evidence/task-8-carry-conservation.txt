# Task 8: Carry Conservation Evidence

## Conservation Equation
The implementation enforces the following conservation equation:

```
cohortTotalClaimed + cohortCarryRemaining ≈ cohortTotalEntitlement
```

(Within rounding tolerance of 10 wei)

## Implementation

### In realizeLoss():
```solidity
epoch.cohortTotalAccrued = epoch.cohortTotalClaimed + epoch.cohortCarryRemaining;
```

This ensures that after loss realization, the cohort's total accrued equals the sum of claimed and remaining carry.

### Verification in Tests:
```solidity
uint256 leftSide = _getEpochCohortClaimed(epochId) + _getEpochCohortCarryRemaining(epochId);
uint256 rightSide = _getEpochCohortEntitlement(epochId);
assertApproxEqAbs(leftSide, rightSide, 10);
```

## Ledger Invariants Maintained

### Per-Request Invariants:
1. `0 <= claimed <= accrued <= entitlement`
2. `carryRemaining + carryDeducted == accrued`
3. `assetsClaimable + claimed == entitlement - accrued`

### Per-Cohort Invariants:
1. `cohortTotalClaimed <= cohortTotalAccrued`
2. `cohortTotalAccrued <= cohortTotalEntitlement`
3. `cohortCarryRemaining <= cohortTotalAccrued`
4. `cohortTotalClaimed + cohortCarryRemaining == cohortTotalAccrued` (conservation)

## Loss Attribution Impact

### Before Loss:
- cohortTotalAccrued = 1000
- cohortTotalClaimed = 0
- cohortCarryRemaining = 1000
- cohortTotalEntitlement = 1000

### After 50% Loss Realized:
- cohortTotalAccrued = 500
- cohortTotalClaimed = 0 (unchanged)
- cohortCarryRemaining = 500
- cohortTotalEntitlement = 1000 (unchanged)

### Verification:
```
cohortTotalClaimed + cohortCarryRemaining = 0 + 500 = 500 = cohortTotalAccrued ✓
```

## Notes
- Rounding errors of up to 10 wei are allowed due to integer division
- Loss cannot exceed cohortCarryRemaining (enforced by revert)
- Each request's loss is capped at their individual carryRemaining
- Conservation holds at the cohort level, not per-request
