# Task 3: Ledger Invariants Evidence

## Implementation Summary

Added canonical per-user carry ledger semantics to EpochTrancheVault.sol per T1 gap matrix F1-LEDGER-001.

## Struct Changes

### RedemptionRequest (15 fields)
- `entitlement`: Gross entitlement before carry (user's total claim on assets)
- `accrued`: Carry accrued against this request (total carry liability)
- `claimed`: Amount already claimed by user
- `carryRemaining`: Remaining carry liability to be deducted

### Epoch (16 fields)
- `cohortTotalEntitlement`: Sum of all entitlements for the epoch
- `cohortTotalClaimed`: Sum of all claimed amounts across cohort
- `cohortCarryRemaining`: Total remaining carry liability for cohort

## Ledger Invariants

### Per-Request Invariants
1. **Non-negative values**: All ledger fields >= 0 (enforced by uint256)
2. **Claimed <= Accrued**: `claimed <= accrued`
3. **Accrued <= Entitlement**: `accrued <= entitlement`
4. **Carry conservation**: `carryRemaining + carryDeducted == accrued`
5. **Asset conservation**: `assetsClaimable + claimed == entitlement - accrued`

### Cohort-Level Invariants
1. **Claimed <= Entitlement**: `cohortTotalClaimed <= cohortTotalEntitlement`
2. **Carry remaining <= Entitlement**: `cohortCarryRemaining <= cohortTotalEntitlement`

## Implementation Points

### Settlement (_settleEpochChunk)
- Calculates `entitlement` for each request: `(shares * frozenAssets * proRataRatio) / (frozenShares * PRORATA_PRECISION)`
- Calculates `accrued` and `carryRemaining` based on carryAmount
- Updates cohort aggregates: `cohortTotalEntitlement`, `cohortCarryRemaining`

### Redemption (redeem/withdraw)
- Updates `claimed` with assets transferred to user
- Reduces `carryRemaining` by carry deducted
- Updates cohort aggregates: `cohortTotalClaimed`, `cohortCarryRemaining`

### Dust Claim (claimDust)
- Handles remaining carry when claiming dust amounts
- Sets `carryRemaining = 0` and adds remaining to `carryDeducted`

## Verification

The implementation ensures:
- Deterministic carry calculation at settlement
- Consistent on-chain/off-chain ledger state
- No negative carry states possible
- All mutations preserve ledger invariants
