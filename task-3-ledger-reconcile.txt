## Deterministic Carry Remaining Equation

### Canonical Formula
```
carryRemaining = entitlement - claimed
```

This is the ONLY valid formula for calculating carryRemaining. It is:
- **Deterministic**: Same inputs always produce same output
- **Loss-aware**: If claimed > entitlement, carryRemaining becomes negative (revealing the bug)
- **Monotonically decreasing**: carryRemaining never increases (unless entitlement increases)

## Backend Layer Reconciliation

### File: apps/vault-api/src/repositories/entitlementRepository.ts

#### reconcileCarryRemaining() Function (Lines 727-776)
```typescript
async reconcileCarryRemaining(entitlementId: number): Promise<{
  success: boolean;
  oldCarryRemaining?: string;
  newCarryRemaining?: string;
  error?: string;
}> {
  const entitlement = await this.getById(entitlementId);
  if (!entitlement) {
    return { success: false, error: 'Entitlement not found' };
  }

  const entitlementAmount = BigInt(entitlement.entitlement);
  const claimed = BigInt(entitlement.claimed);
  
  // Deterministic calculation: carryRemaining = entitlement - claimed
  const expectedCarryRemaining = entitlementAmount - claimed;
  const currentCarryRemaining = BigInt(entitlement.carryRemaining);

  if (currentCarryRemaining !== expectedCarryRemaining) {
    await this.database
      .update(epochRedemptionEntitlements)
      .set({
        carryRemaining: expectedCarryRemaining.toString(),
        updatedAt: new Date(),
      })
      .where(eq(epochRedemptionEntitlements.id, entitlementId));

    return {
      success: true,
      oldCarryRemaining: currentCarryRemaining.toString(),
      newCarryRemaining: expectedCarryRemaining.toString(),
    };
  }

  return {
    success: true,
    oldCarryRemaining: currentCarryRemaining.toString(),
    newCarryRemaining: currentCarryRemaining.toString(),
  };
}
```

## Reconciliation Flow

### Scenario 1: Normal Claim
```
Initial State:
  entitlement = 1000
  accrued = 500
  claimed = 0
  carryRemaining = 1000

After Claiming 200:
  claimed = 200
  carryRemaining = 1000 - 200 = 800

After Claiming 300 more:
  claimed = 500
  carryRemaining = 1000 - 500 = 500
```

### Scenario 2: Loss-Aware Detection (Bug Scenario)
```
Initial State:
  entitlement = 1000
  accrued = 500
  claimed = 0
  carryRemaining = 1000

Bug: User somehow claims 1200 (more than entitled):
  claimed = 1200
  carryRemaining = 1000 - 1200 = -200  <-- NEGATIVE! BUG DETECTED!
```

The negative carryRemaining immediately signals an invariant violation.

### Determinism Proof

The calculation is deterministic because:
1. **Same inputs**: entitlement and claimed are the only inputs
2. **Pure function**: No external state or randomness
3. **Integer arithmetic**: No floating point errors
4. **Consistent formula**: Same formula used across all layers

### Loss-Awareness Proof

The formula is loss-aware because:
1. **Monotonicity**: claimed only increases, so carryRemaining only decreases
2. **Boundary detection**: If claimed > entitlement, carryRemaining < 0
3. **Immediate visibility**: Negative values are easily detected and logged
4. **Audit trail**: All reconciliations are logged with before/after values
