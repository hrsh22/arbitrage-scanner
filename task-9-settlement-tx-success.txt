Key Features
------------

1. Transaction Confirmation Waiting:
   - Uses `publicClient.waitForTransactionReceipt()` 
   - Configurable confirmations (default: 1)
   - Configurable timeout (default: 120 seconds)

2. Retry Logic:
   - Exponential backoff (1s, 2s, 4s, 8s...)
   - Default 3 retries per operation
   - Applied to all contract calls and confirmation waits

3. Structured Error Handling:
   - Returns `{ success: false, error: string }` on failure
   - Includes txHash in error response if transaction was submitted
   - Logs detailed error information with context

4. Tx Hash Persistence:
   - Returns txHash for settleEpoch in success response
   - Includes txHash in error responses where applicable
   - Logs all transaction hashes (freeze, settle, finalize)

Settlement Flow
---------------

1. Check settlement readiness (epoch ended)
2. Get settler wallet client
3. If epoch not frozen:
   - Call freezeEpoch(snapshotHash)
   - Wait for confirmation
4. Calculate available assets
5. Call settleEpoch(epochId, availableAssets, carryAmount)
   - Wait for confirmation
6. Call finalizeEpoch(epochId)
   - Wait for confirmation
7. Return settlement result with txHash

Error Scenarios Handled
-----------------------

- Missing settler key configuration
- Epoch not found
- Epoch already settled/finalized
- Epoch not ended yet
- Failed to initialize settler wallet
- Freeze transaction failed
- Settlement transaction failed
- Finalize transaction failed
- Transaction confirmation timeout
