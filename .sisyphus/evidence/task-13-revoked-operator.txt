# Task 13: Edge Case Tests - Revoked Operator Evidence

## Summary
Successfully implemented edge case tests for revoked operator actions in WeeklyEpochVault.

## Test Results
All revoked operator tests pass (5 tests):

1. **testRevokedOperatorCannotRequestRedeem** ✅
   - Verifies that an operator, once revoked, cannot call requestRedeem on behalf of the owner
   - Reverts with NotOwner(owner, operator) error

2. **testRevokedOperatorCannotRedeem** ✅
   - Verifies that a revoked operator cannot call redeem on behalf of the controller
   - Reverts with NotController(controller, operator) error

3. **testRevokedOperatorCannotWithdraw** ✅
   - Verifies that a revoked operator cannot call withdraw on behalf of the controller
   - Reverts with NotController(controller, operator) error

4. **testRevokedOperatorCannotRequestRedeemForOwner** ✅
   - Verifies revoked operator cannot request redeem for the original owner
   - Reverts with NotOwner(owner, operator) error

5. **testRevokedOperatorCannotRedeemForController** ✅
   - Verifies revoked operator cannot redeem for controller
   - Reverts with NotController(controller, operator) error

## Key Findings

### Operator Lifecycle
- Operator can be granted via `setOperator(operator, true)`
- Operator can be revoked via `setOperator(operator, false)`
- Operator status is stored in `isOperator[controller][operator]` mapping
- Revocation is immediate and takes effect for all subsequent calls

### Authorization Errors
- `NotOwner(address owner, address caller)` - thrown when operator tries to act on behalf of owner after revocation
- `NotController(address controller, address caller)` - thrown when operator tries to redeem/withdraw after revocation

### Edge Cases Covered
- Operator can be re-approved after revocation
- Multiple operators can be set for the same controller
- Operator status is independent per controller (user1's operator doesn't affect user2)
- OperatorSet event is emitted on both approval and revocation
