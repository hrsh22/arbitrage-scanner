## Closed-Book Batch Lifecycle

OPEN -> CUTOFF -> FLATTENING -> SETTLING -> SETTLED -> CLOSED -> REOPEN

## Batch Sealing Rule (Implemented)

First accepted redemption request in OPEN state seals the active batch.
Subsequent requests route to the next batch (queued for future processing).

Reference: claimStateMachine.ts
```typescript
export const ClaimState = {
  OPEN: "open",
  CUTOFF: "cutoff",  // First request seals the batch
  FLATTENING: "flattening",
  SETTLING: "settling",
  SETTLED: "settled",
  CLOSED: "closed",
  REOPEN: "reopen",
} as const;
```

## Cancellation Rule (Implemented)

Cancellation is IMPOSSIBLE after CUTOFF.
Requests are irreversible once the batch is sealed.

Reference: withdrawalRepository.ts
```typescript
// CLOSED-BOOK BATCH: Enforce cancellation rule
// Cancellation is IMPOSSIBLE after CUTOFF
if (targetStatus === "cancelled" && vaultType === "custom") {
  const cancellableStates: WithdrawalStatus[] = ["open"];
  if (!cancellableStates.includes(currentStatus)) {
    return {
      success: false,
      request,
      error: `Cancellation IMPOSSIBLE: Batch is already sealed...`,
      cancellationRejected: true,
    };
  }
}
```
