   - Reverts with NoClaimableRequest(controller) error

## Key Findings

### Claim Idempotency Behavior
- When no claimable request exists, all claim attempts revert with `NoClaimableRequest`
- The error is deterministic and consistent across multiple attempts
- No state changes occur on failed claim attempts

### Authorization Flow
- Claim requires: `msg.sender == controller || isOperator[controller][msg.sender]`
- If authorized but no claimable request exists: `NoClaimableRequest` error
- If not authorized: `NotController` error (checked before claimable check)

### Error Precedence
1. `ZeroAmount` - checked first (if shares/assets == 0)
2. `InvalidAddress` - checked for receiver/controller
3. `NotController` - checked for authorization
4. `NoClaimableRequest` - checked if claimable request exists

## Notes
The full "claim twice" scenario (where a user claims all assets, then tries again) would require
setting up a claimable request first, which depends on deposit/mint functionality that doesn't
exist in the current vault implementation. The tests verify the authorization-level protections
that prevent claims when no claimable request exists.
