# Method Mapping: Old → Canonical Contract

## Breaking Changes Summary

| Aspect | WeeklyEpochVault | EpochTrancheVault (Canonical) | Impact |
|--------|------------------|------------------------------|--------|
| **requestRedeem return** | Always returns 0 (controller-aggregated) | Returns unique requestId | HIGH - All callers must track requestId |
| **Deposit flow** | Instant mint | queueDeposit → processDepositQueue | HIGH - New deposit queue required |
| **Settlement flow** | settleEpoch directly | freezeEpoch → settleEpoch | HIGH - Two-step settlement |
| **Cancel redemption** | cancelRedeemRequest(shares) | cancelRedeemRequest(requestId) | HIGH - Requires requestId |
| **Claim** | redeem(shares, receiver, controller) | redeem(requestId, shares, receiver) | HIGH - Requires requestId |
| **Controller mapping** | controller → request (aggregated) | controller → requestId → request | HIGH - Extra lookup step |

## Detailed Method Mapping

### Deposit Flow

| Old (WeeklyEpochVault) | New (EpochTrancheVault) | Notes |
|------------------------|-------------------------|-------|
| `deposit(uint256 assets)` (instant) | `queueDeposit(uint256 assets)` | Now queues for next epoch |
| N/A | `processDepositQueue(uint256 epochId, uint256 start, uint256 end)` | New: batch process deposits |
| N/A | `totalQueuedAssets()` | New: view total queued |

**Migration Path:**
```solidity
// OLD: Instant mint
vault.deposit(assets); // returns shares immediately

// NEW: Queue + process
uint256 requestId = vault.queueDeposit(assets); // queue for next epoch
// ... epoch advances ...
vault.processDepositQueue(epochId, startIndex, endIndex); // mint shares
```

### Redemption Flow

| Old (WeeklyEpochVault) | New (EpochTrancheVault) | Notes |
|------------------------|-------------------------|-------|
| `requestRedeem(shares, controller, owner)` returns 0 | `requestRedeem(shares, controller, owner)` returns requestId | **BREAKING: Track requestId!** |
| `cancelRedeemRequest(uint256 shares)` | `cancelRedeemRequest(uint256 requestId)` | **BREAKING: Pass requestId** |
| `redeem(uint256 shares, address receiver, address controller)` | `redeem(uint256 requestId, uint256 shares, address receiver)` | **BREAKING: Pass requestId** |
| `withdraw(uint256 assets, address receiver, address controller)` | `withdraw(uint256 requestId, uint256 assets, address receiver)` | **BREAKING: Pass requestId** |
| `pendingRedeemRequest(0, controller)` | `redemptionRequests(requestId)` then check status | **BREAKING: Lookup by requestId** |
| `claimableRedeemRequest(0, controller)` | `redemptionRequests(requestId)` then check status | **BREAKING: Lookup by requestId** |

**Migration Path:**
```solidity
// OLD: Controller-aggregated model (always requestId = 0)
vault.requestRedeem(shares, controller, owner); // returns 0
// ... wait for settlement ...
vault.redeem(shares, receiver, controller);

// NEW: Unique requestId model
uint256 requestId = vault.requestRedeem(shares, controller, owner); // returns actual requestId
// Store requestId!
// ... wait for settlement ...
vault.redeem(requestId, shares, receiver); // pass requestId
```

### Settlement Flow

| Old (WeeklyEpochVault) | New (EpochTrancheVault) | Notes |
|------------------------|-------------------------|-------|
| `settleEpoch(epochId, availableAssets)` | `freezeEpoch(snapshotHash)` then `settleEpoch(epochId, availableAssets, carryAmount)` | **BREAKING: Two-step with freeze** |
| `settleEpochChunked(epochId)` | N/A | Removed - handle in single settleEpoch |
| `getSettlementStatus(epochId)` | `epochs(epochId)` | Returns Epoch struct |

**Migration Path:**
```solidity
// OLD: Single-step settlement
vault.settleEpoch(epochId, availableAssets);
// or chunked
vault.settleEpochChunked(epochId);

// NEW: Two-step settlement with carry
vault.freezeEpoch(snapshotHash); // First freeze
// ... wait for epoch end ...
vault.settleEpoch(epochId, availableAssets, carryAmount); // Then settle with carry
```

  controller: Address;
  owner: Address;
  shares: bigint;
  assets: bigint;

  shares: bigint;

  carryDeducted: bigint;    // NEW: track carry

## Intentional Breaking Points

These changes are **intentional** and **not backward compatible**:

1. **Controller-aggregated → Unique requestId**: Enables partial cancellations, better tracking
2. **Instant mint → Deposit queue**: Prevents gaming, allows batch processing
3. **Single-step settlement → Freeze + Settle**: Enables snapshot verification, proper carry calculation
4. **Added carry accrual**: Performance fee distribution mechanism

## Compatibility Posture

| Component | Compatibility |

| Provider integrations | **BROKEN** - Must track requestIds |
