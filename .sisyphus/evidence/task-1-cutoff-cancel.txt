## Cancellation Rule Implemented

Cancellation is IMPOSSIBLE after CUTOFF.
Requests are irreversible once the batch is sealed.

## Implementation Details

### claimStateMachine.ts
Valid operations per state:
- OPEN: [VIEW, REQUEST, CANCEL] - Cancellation allowed
- CUTOFF: [VIEW] - No cancellation possible
- FLATTENING: [VIEW, VIEW_HISTORY] - No cancellation
- SETTLING: [VIEW, VIEW_HISTORY] - No cancellation
- SETTLED: [VIEW, CLAIM, VIEW_HISTORY] - Claims only

### withdrawalRepository.ts
```typescript
/** Valid state transitions for closed-book batch vaults */
export const validCustomTransitions: Record<WithdrawalStatus, WithdrawalStatus[]> = {
  // OPEN: Accepting requests, cancellation allowed
  open: ["cutoff", "cancelled"],
  // CUTOFF: Batch sealed, no cancellation possible
  cutoff: ["flattening"],
  // ... rest of states don't allow cancellation
};
```

State transition validation:
```typescript
// CLOSED-BOOK BATCH: Enforce cancellation rule
// Cancellation is IMPOSSIBLE after CUTOFF
if (targetStatus === "cancelled" && vaultType === "custom") {
  const cancellableStates: WithdrawalStatus[] = ["open"];
  if (!cancellableStates.includes(currentStatus)) {
    return {
      success: false,
      request,
      error: `Cancellation IMPOSSIBLE: Batch is already sealed...`,
      cancellationRejected: true,
    };
  }
}
```
