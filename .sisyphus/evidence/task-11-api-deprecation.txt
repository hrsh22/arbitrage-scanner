DEPRECATED ROUTES
--------------------------------------------------------------------------------

The following routes return HTTP 410 Gone status with replacement guidance:

1. POST /api/vaults/:vaultId/legacy-claim
   Status: 410 Gone
   Replacement: POST /api/vaults/:vaultId/requests/:requestId/claim
   Reason: New claim flow with lifecycle fields and proper state machine

2. GET /api/vaults/:vaultId/legacy-status
   Status: 410 Gone
   Replacement: GET /api/vaults/:vaultId/redemptions
   Reason: New redemption state with corrected lifecycle fields

RATIONALE
--------------------------------------------------------------------------------

The legacy endpoints used stale lifecycle semantics:
- pending/settled terminology (replaced with cohort-carry lifecycle)
- totalRealizedUsdc/totalClaimedUsdc (replaced with accrued/claimed/entitlement)
- No support for dust override or threshold policies

The new endpoints enforce:
- Corrected lifecycle: entitlement -> accrued -> claimed -> carryRemaining
- Minimum claim threshold (1 USDC) to prevent dust attacks
- Dust override eligibility for edge cases
- Proper claim state machine validation

CLIENT MIGRATION GUIDE
--------------------------------------------------------------------------------

FROM: POST /api/vaults/1/legacy-claim
TO:   POST /api/vaults/1/requests/{requestId}/claim

FROM: GET /api/vaults/1/legacy-status
TO:   GET /api/vaults/1/redemptions

Key field mappings:
- totalRealizedUsdc -> accrued
- totalClaimedUsdc -> claimed
- NEW: entitlement (total entitled amount)
- NEW: carryRemaining (remaining to be carried)
- NEW: dustOverrideEligible (threshold bypass flag)
